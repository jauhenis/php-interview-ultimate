# 13. Кэширование и Redis

### Что такое кэширование?

<span className="badge badge--success margin-bottom--md">Junior</span>

**Ответ:** Сохранение данных во временном хранилище (например, в оперативной памяти) для более быстрого извлечения при последующих запросах.

---

### Что такое Redis и для чего его используют, кроме кэширования?

<span className="badge badge--success margin-bottom--md">Junior</span>

**Ответ:** Redis — это in-memory хранилище «ключ — значение» со встроенными структурами данных. Помимо кэша, в PHP-проектах его используют для сессий, очередей, счётчиков, rate limiting и распределённых блокировок.

[Подробное руководство](../answers/redis.md)

---

### Что такое TTL в Redis и как истекают ключи?

<span className="badge badge--success margin-bottom--md">Junior</span>

**Ответ:** TTL — время жизни ключа, задаётся через `EXPIRE key 60` или `SET key value EX 60`. `TTL key` возвращает оставшиеся секунды. Redis удаляет истёкший ключ при обращении к нему и в периодическом фоновом цикле.

[Подробное руководство](../answers/redis.md)

---

### Почему Redis быстрый?

<span className="badge badge--success margin-bottom--md">Junior</span>

**Ответ:** Данные хранятся в оперативной памяти, а команды выполняет один поток по очереди, поэтому им не нужны блокировки. Обратная сторона: одна медленная команда задерживает всех остальных клиентов.

---

### Redis и Memcached: сравнение

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:**

- **Redis:** Поддерживает различные типы данных (строки, списки, множества и др.), персистентность и механизм pub/sub.
- **Memcached:** Простое хранилище «ключ-значение», в основном для простого кэширования.
  [Сравнение Redis и Memcached](../answers/caching.md)

---

### Какие типы данных Redis используются чаще всего?

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:** Строки для значений и счётчиков, хеши для объектов, списки для простых очередей, множества для уникальных значений и сортированные множества для рейтингов. Полный список — в [документации Redis по типам данных](https://redis.io/docs/latest/develop/data-types/).

---

### Какие стратегии кэширования вы знаете?

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:** В PHP чаще всего используют cache-aside: читаем из кэша, а при промахе загружаем данные из БД и сохраняем их в кэш. Другие стратегии: read-through, write-through, write-behind и refresh-ahead.

[Подробное руководство](../answers/redis.md)

---

### Как инвалидировать кэш?

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:** Задать TTL, удалить ключ после коммита транзакции в БД или сменить версию либо тег, чтобы сбросить группу ключей. Удалять ключ надёжнее, чем записывать новое значение: так параллельные записи не оставят в кэше устаревшие данные.

[Подробное руководство](../answers/redis.md)

---

### Что происходит, когда у Redis заканчивается память?

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:** При достижении `maxmemory` Redis применяет политику из `maxmemory-policy`. Политика по умолчанию `noeviction` отклоняет запись. Для Redis, который служит только кэшем, обычно выбирают `allkeys-lru` или `allkeys-lfu`.

[Подробное руководство](../answers/redis.md)

---

### Как работает персистентность в Redis: RDB vs AOF?

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:** RDB периодически сохраняет снимки: они компактные и быстро загружаются, но записи после последнего снимка теряются. AOF записывает в журнал каждую операцию записи. С `appendfsync everysec` теряется не больше секунды записей.

[Подробное руководство](../answers/redis.md)

---

### Почему не стоит использовать `KEYS *` на проде?

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:** `KEYS` обходит все ключи за один вызов и блокирует остальных клиентов до конца обхода. Используйте `SCAN`: он перебирает ключи с курсором небольшими порциями.

[Подробное руководство](../answers/redis.md)

---

### Чем отличается pipelining от транзакций (MULTI/EXEC)?

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:** Pipelining отправляет много команд за один сетевой round trip, но между ними могут выполниться команды других клиентов. `MULTI`/`EXEC` выполняет накопленные команды единым изолированным блоком, но не откатывает их, если одна из команд завершилась ошибкой.

[Подробное руководство](../answers/redis.md)

---

### phpredis vs Predis: в чём разница?

<span className="badge badge--primary margin-bottom--md">Middle</span>

**Ответ:** phpredis — расширение PHP, написанное на C. Predis — Composer-пакет, написанный на PHP.

[Подробное руководство](../answers/redis.md)

---

### Что такое cache stampede и как его предотвратить?

<span className="badge badge--warning margin-bottom--md">Senior</span>

**Ответ:** Когда истекает часто читаемый ключ, множество запросов одновременно получают промах и пересчитывают одно и то же значение, перегружая БД. Пусть значение пересчитывает один процесс под блокировкой, обновляйте его до истечения или отдавайте старое значение на время обновления.

[Подробное руководство](../answers/redis.md)

---

### Что такое cache penetration и cache avalanche?

<span className="badge badge--warning margin-bottom--md">Senior</span>

**Ответ:** Penetration — запросы к несуществующим данным всегда доходят до БД. Кэшируйте пустой результат на короткое время. Avalanche — одновременно истекает много ключей или узел кэша перезапускается пустым. Добавляйте к TTL случайный разброс.

[Подробное руководство](../answers/redis.md)

---

### Redis Sentinel vs Redis Cluster: в чём разница?

<span className="badge badge--warning margin-bottom--md">Senior</span>

**Ответ:** Sentinel добавляет автоматический failover для одного мастера и его реплик, но не шардирует данные. Cluster распределяет ключи по нескольким мастерам и включает failover.

[Подробное руководство](../answers/redis.md)

---

### Как реализовать rate limiter на Redis?

<span className="badge badge--warning margin-bottom--md">Senior</span>

**Ответ:** Самый простой вариант — фиксированное окно: увеличивайте через `INCR` ключ для пользователя и минуты, а при первом запросе задавайте ему TTL. Выполняйте обе команды в одном Lua-скрипте, чтобы они выполнились атомарно.

[Подробное руководство](../answers/redis.md)

---

### Redis Pub/Sub vs Redis Streams: что и когда использовать?

<span className="badge badge--warning margin-bottom--md">Senior</span>

**Ответ:** Pub/Sub доставляет сообщение только подписчикам, подключённым в этот момент, и не хранит его. Streams хранят сообщения, а группы потребителей позволяют воркерам подтверждать каждое сообщение, поэтому оно не потеряется, пока воркер недоступен.

[Подробное руководство](../answers/redis.md)
